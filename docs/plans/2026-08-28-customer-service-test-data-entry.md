# Customer Service Test Data Entry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an approval-gated demo plugin with five Web tools that strictly create inventory, orders, logistics, returns, and refunds in the existing SQLite customer-service acceptance database.

**Architecture:** Extend the storage contract and both storage adapters with strict insert operations, keep all normalization and cross-entity validation in `CustomerStateService`, and expose five narrow tools from a new demo-only plugin. The plugin never imports SQLite; it calls `customerState`, publishes committed domain events through `customerEvents`, and relies on the demo Bundle for isolation from production.

**Tech Stack:** TypeScript 6.0.3, Node.js 22.19+ built-in `node:sqlite`, Cordis 4.0.1, DeepSeek Harness tools 0.1.1-rc.2, Vitest 4.1.8, pnpm 11.7.0, YAML Bundle patches.

**Spec:** `docs/superpowers/specs/2026-08-28-customer-service-test-data-entry-design.md`

## Global Constraints

- The tools are exactly `test_create_inventory`, `test_create_order`, `test_create_logistics`, `test_create_return`, and `test_create_refund`.
- Every tool requires a Harness `kind: 'ask'` decision before execution.
- The new plugin is present only in `dsh-bundle-customer-service-demo`; production remains exactly 7 nodes.
- Every operation is strict create: duplicate identity or duplicate order-level return/refund is rejected and never becomes an update.
- Business IDs are trimmed and uppercased; timestamps and `version = 1` are generated by `CustomerStateService`.
- Cross-entity validation is strict: order item SKUs, logistics orders, return orders, refund orders, and optional refund return IDs must exist and agree.
- Plugins do not import SQLite and no API accepts SQL or arbitrary untyped JSON.
- Database path remains `<main-checkout>/data/customer-service.db`; database, WAL, SHM, and backups remain Git-ignored.
- Existing query and mutation tool names and result contracts must not change.
- Node 22's `ExperimentalWarning` for `node:sqlite` is accepted; every other warning or failure is investigated.
- Use TDD for every code task: prove RED, implement the smallest complete change, prove GREEN, then commit.
- Preserve the user's unrelated untracked `.DS_Store`.
