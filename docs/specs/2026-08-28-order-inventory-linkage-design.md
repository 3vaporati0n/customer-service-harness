# 订单到库存查询模块衔接设计

## 目标

让 `query_order` 的成功结果直接提供订单商品明细，使模型能够从订单号取得 SKU，再调用独立的 `query_inventory` 工具；自然语言跨模块查询不得依赖 Bash 或直接读取 SQLite。

## 范围

- `query_order` 成功结果新增必填 `items` 数组。
- 每个商品包含 `sku`、`quantity` 和 `unitPrice`。
- 中文渲染在原有订单状态文案后追加商品明细，确保模型在只看到渲染文本时也能取得 SKU。
- `query_order` 的名称、参数、状态字段、未找到分支和异常语义保持不变。
- `query_inventory` 保持独立，不在订单插件中直接读取或返回库存。

## 数据流

自然语言订单查询 → `query_order(orderId)` → 返回订单状态与 `items`
→ 后续自然语言库存问题 → 模型提取 `items[].sku`
→ `query_inventory(sku)` → 返回实时库存。

## 兼容策略

旧调用方依赖的字段和值继续存在；兼容测试从“整个对象必须完全相等”调整为“旧字段必须保持相等”，因为新增字段是有意的向后兼容扩展。未找到订单的结果仍与旧插件完全一致。

## 验收标准

1. `ORDER-1002` 的 `query_order` 结果包含 `SKU-1002`、数量 `1`、单价 `399`。
2. 输出 Schema 将 `items` 声明为必填、严格的对象数组。
3. 中文渲染包含 SKU，原状态信息仍完整保留。
4. 未找到订单和服务异常行为不变。
5. 全量构建、测试和 Bundle 验证通过。
6. 重新安装 Web Profile 后，自然语言连续询问订单与库存时，只调用客服工具，不执行 Bash。
